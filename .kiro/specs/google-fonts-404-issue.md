# Google Fonts 404 Issue - Red Hat Display

**Status:** Design  
**Created:** 2026-09-24  
**Updated:** 2026-09-24 (Moved to Design phase)  
**Priority:** High  

---

## Problem Statement

Google Fonts is returning HTTP 404 errors for Red Hat Display woff2 files. While the CSS endpoint at `fonts.googleapis.com` loads successfully and contains valid `@font-face` declarations, the actual font file URLs it references on `fonts.gstatic.com` are broken.

### Failing Example
- **URL:** `https://fonts.gstatic.com/s/redhatdisplay/v21/8vIq7wUr0m80wwYf0QCXZzYzUoTK8RZQvRd-D1NYbmyWEEMbCa8AIHrEG1nO6OOJzScMKMPL.woff2`
- **Error:** HTTP 404 Not Found
- **CSS Source:** `https://fonts.googleapis.com/css2?family=Red+Hat+Display:wght@400;700&display=swap`
- **Discovered:** 2026-08-13 during GitLab Pages deployment
- **Note:** Red Hat Text font loaded successfully; only Display variant affected

### Current Investigation Findings ✅

**Investigation Completed:** 2026-09-24

#### Key Findings Summary
1. **woff2 URLs definitively return 404**, but TTF URLs work correctly
2. **Google Fonts CSS API now serves TTF format** instead of woff2 for all Red Hat fonts
3. **Issue is format-specific, not font-specific** - affects all three Red Hat font families
4. **Similar pattern found in other fonts** - related issues in google/fonts repository

#### Detailed Test Results

**Red Hat Display (v21 on Google Fonts):**
- ✅ All weights tested (300, 400, 500, 600, 700, 800, 900) - TTF files return HTTP 200
- ✅ Italic styles tested (400, 700) - TTF files work correctly  
- ❌ woff2 format - Confirmed HTTP 404
- 📍 Example working TTF: `https://fonts.gstatic.com/s/redhatdisplay/v21/8vIf7wUr0m80wwYf0QCXZzYzUoTK8RZQvRd-D1NYbmyWckg.ttf`
- 📍 Example failing woff2: `https://fonts.gstatic.com/s/redhatdisplay/v21/8vIq7wUr0m80wwYf0QCXZzYzUoTK8RZQvRd-D1NYbmyWEEMbCa8AIHrEG1nO6OOJzScMKMPL.woff2`

**Red Hat Text (v19 on Google Fonts):**
- ✅ Tested weights 400, 700 - TTF files return HTTP 200
- Format serving: Currently returning TTF instead of woff2

**Red Hat Mono (v16 on Google Fonts):**
- ✅ Tested weights 400, 700 - TTF files return HTTP 200  
- Format serving: Currently returning TTF instead of woff2

#### Related Issues Found

**Issue #10804 - Figtree v9 WOFF2 404s:**
- Similar problem: CSS API intermittently returns non-existent woff2 URLs
- Pattern: 404 URL generated by Google Fonts CSS API itself
- Frequency: ~1% of requests in Figtree case
- Status: Indicates infrastructure issue between CSS generation and asset serving

**Issue #1642 - .woff files returning 404s (2018):**
- Historical precedent: Google Fonts has removed format support before
- Previous pattern: User-agent based decisions on format serving
- Resolution: Google shifted from .woff to .woff2 format
- Current situation: May be similar shift away from woff2 to TTF

**Issue #4700 - Red Hat Font Update (2022):**
- Shows Red Hat fonts were updated to v1.023 in 2022
- No specific mention of woff2 issues at that time

#### Version Analysis

**Repository Version:**
- Semantic versioning: v4.0.2 (released 2021-04-28)
- Latest commits: 2026-04-28 (weight updates)
- Font sources updated with new variable fonts in 2024-2025

**Google Fonts Version:**
- Display: v21 (incremental versioning system)
- Text: v19
- Mono: v16
- Version systems are incompatible - cannot directly correlate

**Copyright dates:** 2021 in metadata files

#### Root Cause Assessment

**Most Likely Explanation:**
Google Fonts infrastructure issue where woff2 files were not properly deployed for v21 of Red Hat Display (and possibly other versions). Google's CSS API has adapted by serving TTF format as a fallback/workaround.

**Evidence:**
1. The same CSS endpoint URL returns different formats over time
2. Similar issues reported with other fonts (Figtree #10804)
3. TTF files exist and work, suggesting deployment/sync issue with woff2
4. Historical pattern of Google Fonts adjusting format serving strategy

**User Impact:**
- **Low current impact** - Google Fonts automatically serves working TTF files
- **Historical impact** - Users who cached woff2 CSS references may see 404s
- **Performance impact** - TTF files are larger than woff2 (~20-40% size difference)

## Self-Hosting Fonts (Recommended)

Self-hosting gives you full control over font delivery, better performance, and immunity from third-party service issues.

### Option 1: Direct Download from Repository

1. **Download fonts from this repository:**
   - OTF files: `fonts/Proportional/RedHatDisplay/otf/`
   - TTF files: `fonts/Proportional/RedHatDisplay/ttf/`
   - WOFF2 files: `fonts/Proportional/RedHatDisplay/webfonts/`
   - Variable fonts: `fonts/Proportional/RedHatDisplay/variable/`

2. **Add fonts to your project:**
   ```
   your-project/
   ├── fonts/
   │   ├── RedHatDisplay-Regular.woff2
   │   ├── RedHatDisplay-Bold.woff2
   │   └── ...
   └── css/
       └── fonts.css
   ```

3. **Create CSS @font-face declarations:**
   ```css
   @font-face {
     font-family: 'Red Hat Display';
     src: url('../fonts/RedHatDisplay-Regular.woff2') format('woff2');
     font-weight: 400;
     font-style: normal;
     font-display: swap;
   }

   @font-face {
     font-family: 'Red Hat Display';
     src: url('../fonts/RedHatDisplay-Bold.woff2') format('woff2');
     font-weight: 700;
     font-style: normal;
     font-display: swap;
   }
   ```

### Option 2: CDN via jsDelivr (No build required)

Use jsDelivr to serve fonts directly from GitHub releases:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/RedHatOfficial/RedHatFont@latest/fonts/proportional/RedHatDisplay/RedHatDisplay.css">
```

Or for specific font files:
```css
@font-face {
  font-family: 'Red Hat Display';
  src: url('https://cdn.jsdelivr.net/gh/RedHatOfficial/RedHatFont@latest/fonts/Proportional/RedHatDisplay/webfonts/RedHatDisplay-Regular.woff2') format('woff2');
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
```

**jsDelivr Benefits:**
- ✅ Automatic CDN distribution
- ✅ Versioned releases (use `@4.0.2` for specific version)
- ✅ Free and reliable
- ✅ No third-party account needed

### Option 3: npm Package

Install via npm for build-tool integration:

```bash
npm install @fontsource/red-hat-display
```

Then import in your JavaScript/CSS:
```javascript
import '@fontsource/red-hat-display'; // Defaults to 400 weight
import '@fontsource/red-hat-display/700.css'; // Bold
```

### Performance Tips

1. **Use woff2 format** - Best compression, supported by all modern browsers
2. **Subset fonts** - Include only characters you need
3. **Use font-display: swap** - Prevents invisible text during load
4. **Preload critical fonts:**
   ```html
   <link rel="preload" href="/fonts/RedHatDisplay-Regular.woff2" as="font" type="font/woff2" crossorigin>
   ```
5. **Consider variable fonts** - One file for all weights (see `/variable` directory)
```

### 4.1 Monitoring Script Design

**File:** `.github/workflows/test-google-fonts.yml`

**Purpose:** Automated weekly check of Google Fonts URLs

**Script Logic:**
```yaml
name: Test Google Fonts Availability

on:
  schedule:
    - cron: '0 9 * * 1'  # Every Monday at 9 AM UTC
  workflow_dispatch:  # Allow manual trigger

jobs:
  test-fonts:
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout repository
        uses: actions/checkout@v3
      
      - name: Test Red Hat Display
        run: |
          echo "Testing Red Hat Display..."
          
          # Test CSS endpoint
          CSS_URL="https://fonts.googleapis.com/css2?family=Red+Hat+Display:wght@400;700&display=swap"
          curl -f -s "$CSS_URL" > display.css || exit 1
          
          # Extract and test first font URL
          FONT_URL=$(grep -oP 'url\(\K[^)]+' display.css | head -1)
          echo "Testing font URL: $FONT_URL"
          curl -f -I "$FONT_URL" || exit 1
          
          # Check if woff2 format is available
          if echo "$FONT_URL" | grep -q "woff2"; then
            echo "✅ woff2 format available"
          else
            echo "⚠️ Warning: Not serving woff2 format"
          fi
      
      - name: Test Red Hat Text
        run: |
          echo "Testing Red Hat Text..."
          CSS_URL="https://fonts.googleapis.com/css2?family=Red+Hat+Text:wght@400;700&display=swap"
          curl -f -s "$CSS_URL" > text.css || exit 1
          FONT_URL=$(grep -oP 'url\(\K[^)]+' text.css | head -1)
          curl -f -I "$FONT_URL" || exit 1
      
      - name: Test Red Hat Mono
        run: |
          echo "Testing Red Hat Mono..."
          CSS_URL="https://fonts.googleapis.com/css2?family=Red+Hat+Mono:wght@400;700&display=swap"
          curl -f -s "$CSS_URL" > mono.css || exit 1
          FONT_URL=$(grep -oP 'url\(\K[^)]+' mono.css | head -1)
          curl -f -I "$FONT_URL" || exit 1
      
      - name: Create issue on failure
        if: failure()
        uses: actions/github-script@v6
        with:
          script: |
            github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: '🚨 Google Fonts availability check failed',
              body: 'Automated testing detected an issue with Google Fonts distribution. Check the [workflow run](${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}) for details.',
              labels: ['google-fonts', 'automated-alert']
            })
```

### 4.2 Manual Testing Checklist

**File:** `.github/GOOGLE_FONTS_CHECKLIST.md`

**Content:**
```markdown
# Google Fonts Testing Checklist

Use this checklist when releasing new font versions or investigating issues.

## Pre-Release Testing

Before submitting fonts to Google Fonts:

- [ ] Test all font files locally
- [ ] Verify metadata is correct
- [ ] Check version numbers
- [ ] Test variable fonts
- [ ] Review CHANGELOG

## Post-Release Verification

After fonts are live on Google Fonts:

- [ ] Test CSS endpoint for all three families
- [ ] Verify woff2 URLs are accessible
- [ ] Check all weight variations
- [ ] Test italic styles
- [ ] Verify version numbers match expectations
- [ ] Test from multiple geographic regions
- [ ] Check browser console for errors

## CSS Endpoints to Test

```bash
# Red Hat Display
curl "https://fonts.googleapis.com/css2?family=Red+Hat+Display:wght@300;400;500;600;700;800;900&display=swap"

# Red Hat Text  
curl "https://fonts.googleapis.com/css2?family=Red+Hat+Text:wght@300;400;500;600;700&display=swap"

# Red Hat Mono
curl "https://fonts.googleapis.com/css2?family=Red+Hat+Mono:wght@300;400;500;600;700&display=swap"
```

## Font URL Testing

Extract URLs from CSS and test directly:
```bash
# Extract first font URL
FONT_URL=$(curl -s "CSS_URL_HERE" | grep -oP 'url\(\K[^)]+' | head -1)

# Test with curl
curl -I "$FONT_URL"

# Should return: HTTP/2 200
```

## Issue Reporting

If problems found:
1. Document exact URLs that fail
2. Note HTTP status codes
3. Check if issue is intermittent
4. File issue in google/fonts repository
5. Update GOOGLE_FONTS_STATUS.md
6. Notify stakeholders
```
